# Architecture

## The contract: storyboard.json + timing.json

`storyboard.json` (validated against `schema/storyboard.schema.json`) is the
single source of truth every stage reads: title, language, the shared
`style_block` and `character_sheet` (so every image prompt repeats the same
description instead of drifting), the 12 `shots` (id, reason, planned
`duration_s`, `image_prompt`, `motion_prompt`, `overlay_text`, per-shot
`narration` text/voice, `subtitle_en`), the `music` spec, and the `end_card`.
It is never mutated by the pipeline.

`outputs/timing.json` is generated by the `narration` stage and is the
narration-driven source of truth every later stage reads instead of
storyboard.json's planned `duration_s`: per shot, `narration_duration_s` (the
actual TTS audio length) and `effective_duration_s`. The `assemble` stage
paces on `narration_duration_s` directly (plus a small fixed pad) rather than
`effective_duration_s`, since the latter pads a shot to its storyboard-era
planned screen time even when the narration finishes well before that - see
FAILURES.md.

## Content-addressed caching (`pipeline/cache.py`)

Every stage computes a cache key from a canonical JSON dict of exactly what
determines its output for one shot (prompt text, style block, voice, model
ids, seed, an upstream file's hash where relevant), hashes it, and writes to
`outputs/<stage>/<shot_id>_<key>.<ext>`. Re-running a stage with unchanged
inputs is a no-op (`is_cached`); editing one shot's prompt changes only that
shot's key, leaving its siblings untouched. `--force` bypasses the check.

## Retry and model fallback (`pipeline/http.py`)

`request_with_retry` backs off with jitter on 429/500/502/503/504 and network
errors, honouring `Retry-After`. `call_with_model_fallback(models, call_fn)`
tries each model in order, moving to the next on any `HttpCallError` that
isn't a `FatalHttpError` (400/401/403, which stops immediately - no point
retrying a bad request against a second model). This is what let narration
keep working when `gemini-3.8-flash-tts` hit its daily quota: the fallback
model became primary with no code change.

## Structured logging (`pipeline/runs_log.py`)

Every model/GPU call (including failed attempts, and GPU minutes from a
Kaggle-imported clip's own `gpu_log.json`) is appended as one JSON line to
`runs.jsonl`: timestamp, stage, shot id, model, params (secrets redacted),
status, latency, GPU minutes, cost, cache key, output path. This is the
record `COSTS.md` is built from, and what lets a failure be diagnosed after
the fact without re-running anything. Pure local ffmpeg operations (Ken Burns
clips, the placeholder score bed, everything in `assemble.py`) are not
model/GPU calls and are not logged here - see `ffmpeg_utils.py`.

## Stage summary

| stage | input | output | fallback / import |
|---|---|---|---|
| `validate` | storyboard.json | pass/fail | - |
| `smoke` | .env | per-provider reachability | - |
| `narration` | storyboard.json | `outputs/narration/*.wav`, `outputs/timing.json` | - (always real Gemini TTS) |
| `radio` | timing.json | `outputs/final/radio_cut.mp4` | - (narration-only prototype) |
| `reference` | storyboard.json | `outputs/reference/cand*.jpg`, then `golden.jpg` | - |
| `keyframes` | storyboard.json | `outputs/keyframes/*.jpg` | - |
| `shots` | timing.json + keyframe | `outputs/shots/*.mp4` | `--fallback` Ken Burns / `--import-dir` Wan 2.2 |
| `music` | storyboard.json + timing.json | `outputs/music/score_*.wav` | `--fallback` placeholder pad / `--import-dir` ACE-Step |
| `assemble` | all of the above | `outputs/final/{9x16,16x9}.mp4` | picks newest shot clip / score per shot |

## assemble.py: one square master, two crops

Clips and keyframes are composed square (1024x1024) with a centred subject
(`style_block`: "vertical-friendly centred composition"), specifically so a
single master can be cropped two ways instead of rendering each aspect ratio
from scratch:

1. **Per-shot segment**: each shot's clip (looped if the imported clip is
   shorter than needed, trimmed if longer) muxed with its narration (padded
   with silence to the shot's paced duration).
2. **Main track**: segments concatenated (ffmpeg concat demuxer, stream
   copy - safe because every segment is encoded with identical codec
   parameters).
3. **Score**: the picked music bed is looped/trimmed to the film's total
   length, ducked under the full narration track via `sidechaincompress`,
   mixed, and loudness-normalised (`loudnorm`, ~-14 LUFS).
4. **Per aspect ratio**: the square master is scaled so its larger side
   matches the target's larger side, then centre-cropped down to size; English
   subtitles and `overlay_text` price captions are burned in via a generated
   ASS track **after** cropping (not before - burning before crop risks a
   16:9 crop slicing through a 9:16-positioned subtitle, since they survive
   different vertical bands of the square frame). An end card clip is
   appended, then muxed with the shared final audio.

## Doc skeleton rationale

`ETHICS.md`'s consent table is a hard gate per the brief ("if a real person
appears or is voiced without a consent record ... the film scores zero");
everything else here exists so the grading/review process can follow what
was built and why without re-deriving it from the code.
